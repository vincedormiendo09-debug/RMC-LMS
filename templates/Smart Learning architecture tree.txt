Loop 1: The Activity, Submission, Grading & Review Loop (Main Feedback Loop)
This is the most critical loop in your platform. When a teacher posts an activity, it travels through student submission, teacher grading, grade reflect, and student review.

[TEACHER] activity.html ──► [STUDENT] notify.html & activitysubmit.html

[STUDENT] review.html   ◄── [TEACHER] studentwork.html & submissions.html & studentgrades.html





HTML Files to Connect:
TEACHER/activity.html (Trigger): Sends a POST /api/activities request when a teacher creates an assignment.

STUDENT/notify.html & STUDENT/activitysubmit.html (Reaction 1):
notify.html fetches unread activity notifications (GET /api/notifications).
activitysubmit.html fetches assignment details and submits student work (POST /api/submissions).

TEACHER/submissions.html & studentwork.html (Reaction 2):
submissions.html lists pending submissions.
studentwork.html sends the grade and feedback to the backend (POST /api/grades).

STUDENT/studentgrades.html & STUDENT/review.html (Reflection):
studentgrades.html automatically reflects the updated overall grade.
review.html fetches score and teacher comments (GET /api/submissions/:id/review).

ADMIN/studentgrades.html & TEACHER/grades.html (Audit Reflection):
Both pages fetch from the exact same /api/grades database table, updating their respective gradebooks instantly.

Here is the complete **Master Action Blueprint** for your Regis Marie College LMS.

This blueprint maps out the exact technical contracts—**database queries, `localStorage` key contracts, form submission payloads, and navigation routes**—to guarantee that data loops smoothly across **Teacher, Student, and Admin** points of view without breaking state or dropping context.
## 🏛️ Core Architectural Protocols

Before diving into role-specific blue-prints, all pages MUST enforce these three non-negotiable data contracts:

1. **Type-Safe Dual ID Resolution (`getDualTypeIds`)**: Supabase queries matching user IDs, class IDs, or activity IDs must query against both String and Integer forms (`.in('user_id', getDualTypeIds([currentUserId]))`) to prevent `TEXT` vs. `BIGINT` database schema type-mismatch crashes.
2. **Flat Query Aggregation**: Never execute deep nested PostgREST joins like `.select('*, users(*), activities(*), classes(*)')`. Execute flat 2-to-4 step queries in JS and build in-memory lookup maps.
3. **Session Cache Contract**: `localStorage` acts as the cross-page bridge. Never redirect to a workspace page without first committing its primary key into `localStorage`.

-- 1. DYNAMICALLY DROP ALL FOREIGN KEYS TARGETING THE users TABLE
DO $$ 
DECLARE 
    r RECORD;
BEGIN
    FOR r IN (
        SELECT tc.table_schema, tc.table_name, tc.constraint_name
        FROM information_schema.table_constraints AS tc
        JOIN information_schema.key_column_usage AS kcu
          ON tc.constraint_name = kcu.constraint_name
          AND tc.table_schema = kcu.table_schema
        JOIN information_schema.constraint_column_usage AS ccu
          ON ccu.constraint_name = tc.constraint_name
          AND ccu.table_schema = tc.table_schema
        WHERE tc.constraint_type = 'FOREIGN KEY' 
          AND ccu.table_name = 'users'
    ) LOOP
        EXECUTE format('ALTER TABLE %I.%I DROP CONSTRAINT IF EXISTS %I;', r.table_schema, r.table_name, r.constraint_name);
    END LOOP;
END $$;

-- 2. CONVERT users.id PRIMARY KEY TO TEXT
ALTER TABLE users ALTER COLUMN id TYPE TEXT USING id::text;

-- 3. DYNAMICALLY CONVERT ALL USER REFERENCE COLUMNS TO TEXT ACROSS ALL TABLES
DO $$ 
DECLARE 
    r RECORD;
BEGIN
    FOR r IN (
        SELECT table_schema, table_name, column_name
        FROM information_schema.columns
        WHERE table_schema = 'public'
          AND column_name IN ('user_id', 'teacher_id', 'creator_id', 'sender_id', 'receiver_id', 'student_id')
          AND data_type != 'text'
    ) LOOP
        EXECUTE format('ALTER TABLE %I.%I ALTER COLUMN %I TYPE TEXT USING %I::text;', r.table_schema, r.table_name, r.column_name, r.column_name);
    END LOOP;
END $$;

-- 4. DISABLE ROW LEVEL SECURITY (RLS) ON ALL PUBLIC TABLES
DO $$ 
DECLARE 
    r RECORD;
BEGIN
    FOR r IN (
        SELECT table_schema, table_name
        FROM information_schema.tables
        WHERE table_schema = 'public' AND table_type = 'BASE TABLE'
    ) LOOP
        EXECUTE format('ALTER TABLE %I.%I DISABLE ROW LEVEL SECURITY;', r.table_schema, r.table_name);
    END LOOP;
END $$;
